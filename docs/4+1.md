### 1.2 Agrégats principaux

| Agrégat | Service | Invariants clés |
|---------|---------|-----------------|
| `User` | Users | Cycle de vie KYC strict (PendingEmailVerification → Active), SIN chiffré AES-256, MFA optionnel |
| `Account` | Accounts | Solde ≥ 0, devise cohérente, statut (Active / Frozen / Closed) |
| `Transaction` | Transactions | Idempotence par `IdempotencyKey` (unicité DB), source ≠ destination, statut (Pending → Completed / Failed) |

### 1.3 Value Objects

| Value Object | Service | Validation |
|---|---|---|
| `Email` | Users | Format e-mail, toLowerCase |
| `HashedPassword` | Users | Non vide |
| `FullName` | Users | Prénom et nom non vides |
| `Address` | Users | Province canadienne valide, code postal format canadien |
| `EncryptedSin` | Users | Non vide (chiffré AES-256) |
| `PhoneNumber` | Users | Format E.164 |
| `Money` | Accounts / Transactions | Montant ≥ 0, arrondi à 2 décimales |

## 2. Vue Processus (C&C — Composants & Connecteurs)

La vue processus décrit les flux d'exécution runtime entre composants.

### 2.1 Flux UC-01 : Inscription & KYC

```
Client → POST /api/users/register
  → UsersController.Register()
    → ValidationBehavior (FluentValidation)
      → RegisterUserHandler
        → IUserRepository.ExistsByEmailAsync()  [DB users]
        → BCryptPasswordHasher.Hash()
        → AES256Encryptor.Encrypt()   [SIN]
        → User.Register()             [crée domaine, rajoute UserRegisteredDomainEvent]
        → IUserRepository.Add()
        → IUnitOfWork.SaveEntitiesAsync()
            → DispatchDomainEventsAsync()  [MediatR INotificationHandler]
            → SaveChangesAsync()           [PostgreSQL]
        → IJwtService.GenerateEmailValidationToken()
      ← 201 Created { token: "..." }
```

### 2.2 Flux UC-02 : Authentification

```
Client → POST /api/users/login
  → UsersController.Login()
    → LoginUserHandler
        → IUserRepository.FindByEmailAsync()
        → BCryptPasswordHasher.Verify()
        → IJwtService.GenerateLoginToken(login=true|false)
          [purpose=login si email vérifié, sinon purpose=verify-email]
      ← 200 OK { token: "..." }
```

### 2.3 Flux UC-03 : Ouverture de compte

```
Client → POST /api/accounts
  [JWT Bearer, purpose=login]
  → EndpointAuthMiddleware (valide JWT, vérifie purpose)
  → AccountController.OpenAccount()
    → ValidationBehavior
      → OpenAccountHandler
          → Account.Open()   [crée domaine + AccountOpenedDomainEvent]
          → IAccountRepository.Add()
          → IUnitOfWork.SaveChangesAsync()
        ← 201 Created { accountId }
```

### 2.4 Flux UC-05 : Virement bancaire

```
Client → POST /api/transactions
  [JWT Bearer, purpose=login]
  → EndpointAuthMiddleware
  → TransactionController.InitiateTransaction()
    → InitiateTransactionHandler
        → ITransactionRepository.GetByIdempotencyKeyAsync()  [idempotence]
        → Transaction.Initiate()   [+ TransactionCreatedDomainEvent]
        → ITransactionRepository.Add()
        → IUnitOfWork.SaveChangesAsync()
            → DispatchDomainEventsAsync()
                → TransactionCreatedEventHandler.Handle()
                    → [Account-to-Account] POST /api/accounts/transfer (interne)
                    → [Interac] POST /api/users/get-interac (interne) + transfer
      ← 201 Created { id }
```

### 2.5 Flux interne inter-services (appels HTTP internes)

```
Users → Accounts : POST /api/accounts/verify-ownership
  [Header: X-Internal-Secret]
  → EndpointAuthMiddleware (InternalEndpoint) → VerifyOwnershipHandler

Transactions → Accounts : POST /api/accounts/transfer
  [Header: X-Internal-Secret]
  → EndpointAuthMiddleware (InternalEndpoint) → TransferFundsHandler
```

## 5. Vue Scénarios (Use Cases)

### SC-01 : Inscription complète d'un client

**Acteurs :** Client  
**Précondition :** Aucune  
**Postcondition :** Profil utilisateur `Active`, compte ouvert

1. Client envoie `POST /api/users/register` avec données personnelles et SIN.
2. FluentValidation vérifie format e-mail, mot de passe fort (12 car., maj/min/chiffre/spécial), province canadienne, code postal canadien, SIN 9 chiffres, âge ≥ 18 ans.
3. `RegisterUserHandler` hache le mot de passe (BCrypt), chiffre le SIN (AES-256), crée l'agrégat `User` (statut `PendingEmailVerification`), déclenche `UserRegisteredDomainEvent`.
4. Service retourne JWT à but `verify-email`.
5. Client envoie code OTP → `ConfirmEmail()` → statut `PendingKyc`.
6. KYC démarre (`StartKyc()`) et est approuvé (`ApproveKyc()`) → statut `Active`.
7. Client ouvre un compte `POST /api/accounts` → `Account.Open()` avec solde initial 100 CAD.

### SC-02 : Virement entre comptes internes

**Acteurs :** Client authentifié  
**Précondition :** 2 comptes actifs, solde suffisant

1. Client envoie `POST /api/transactions` avec `IdempotencyKey`, `FromAccount`, `Destination` (UUID du compte cible), `DestinationType=Account`, `Amount`.
2. `InitiateTransactionHandler` vérifie idempotence (lookup par `IdempotencyKey`).
3. Si nouvelle transaction : crée `Transaction` (statut `Pending`), déclenche `TransactionCreatedDomainEvent`.
4. `TransactionCreatedEventHandler` appelle `POST /api/accounts/transfer` (appel interne avec `X-Internal-Secret`).
5. `TransferFundsHandler` débit `Account.Debit()`, crédite `Account.Credit()`, sauvegarde en une transaction DB.
6. Transaction passe au statut `Completed`.

### SC-03 : Appel idempotent (rejeu de requête)

**Précondition :** Transaction déjà créée avec même `IdempotencyKey`

1. Client renvoie `POST /api/transactions` avec même `IdempotencyKey`.
2. `InitiateTransactionHandler` retrouve la transaction existante.
3. Retourne `201 Created` avec `AlreadyExists=true` sans re-exécuter l'opération.
